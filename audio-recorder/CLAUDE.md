## Schema rule

Every type that is serialized (config, device state, manifests, and all IPC between the Leptos UI and the Tauri backend, both commands and events) must be defined first in `schemas/*.schema.json`. Use the types generated by `crates/schema` and (de)serialize only through `schema::from_*` / `schema::to_*`, which validate. Never hand-write serde structs for these, and never call `serde_json` / `toml` directly on them. To change a serialized type, edit the schema and rebuild.

Schemas are JSON Schema draft-07 (typify uses schemars 0.8: use `definitions`, not `$defs`). typify does not resolve `$ref`s across files; share types by defining them in one schema file.

## Architecture

Cargo workspace. `default-members` are schema/core/cli; `--workspace` also builds app and ui.

- `schemas/` — JSON Schema sources of truth (`config`, `device-state`, `manifest`, `mix`, `analysis`, `ipc`, `transcript`, `jobs`, `summary`, `llm`, `theme`, `settings`).
- `crates/schema` (`audio-recorder-schema`) — `build.rs` runs typify over `schemas/` and emits one module per schema (e.g. `schema::config`). Exposes the `Schema` trait and validating `from_value`/`to_value`/`from_json_str`/`to_json_string_pretty`/`from_toml_str`. Must stay wasm-compatible (the UI depends on it). Keep constraints that make typify emit newtypes (`pattern`, `minLength`, `enum` on scalars) to a minimum: they make the generated types awkward to construct. To add a schema: add the file, add one line to `SCHEMAS` in `build.rs` (module name, file, root type or `AllDefinitions`); modules, `impl Schema` and validator registration are generated. Add fixtures under `tests/fixtures/<name>/` (`valid-*` / `invalid-*`). `transcript.schema.json` is a session's `transcript.json` and `transcript.live.json`; `jobs.schema.json` is one background task file; `summary.schema.json` is a session's `summary.json`; `llm.schema.json` holds the Ollama and Anthropic request/response bodies (every definition becomes `llm.<Name>`, like `ipc`; response types leave extra properties allowed). `ipc.schema.json` is special: every entry under `definitions` becomes a top-level validated type named `ipc.<Name>`. `theme.schema.json` defines a `Theme` (id, name, `scheme` light/dark, one `Palette` of fixed color tokens). `settings.schema.json` is the persisted UI settings file (currently just `theme`, an id or `system`).
- `crates/core` (`audio-recorder-core`) — UI-free logic.
  - `config`, `paths`: config lookup (first existing of `./config.toml`, `<exe dir>/config.toml`, `~/.config/audio-recorder/config.toml`, no merging between files); XDG paths. `config.example.toml` at the repo root is `include_str!`-embedded and is the authoritative source of defaults: the chosen file is layered over it (`schema::from_toml_layers`) before validation, so add or change defaults there (model file names count as non-explicit only while equal to the example's). The schema `default` keywords must stay in sync (a test checks). `logging`: `tracing` to stderr and to `log_file` (config; default `<tmp>/audio-recorder.log`), filtered by `RUST_LOG` (default `info`); both binaries call `logging::init_from`. Use `tracing` macros for diagnostics; plain `println!` is only for CLI command output. Sessions: `~/.local/share/audio-recorder/sessions/<UTC timestamp>`; device state: `$XDG_STATE_HOME/audio-recorder/devices.json`; settings: `$XDG_STATE_HOME/audio-recorder/settings.json` (`settings::SettingsStore`).
  - `device`: `DeviceKey` = `<input|output>:<PipeWire node.name>`, stable across reconnects.
  - `device_state`: persisted per-device enabled flag (default enabled, remembered while disconnected).
  - `pw`: all PipeWire objects live on one dedicated thread (pipewire-rs is `!Send`); commands in via `pipewire::channel`, events out via crossbeam. Inputs are `Audio/Source` nodes, outputs are `Audio/Sink` nodes captured through their monitor (`stream.capture.sink`). Capture streams use `node.dont-reconnect`.
  - `session`: `Recorder` runs a coordinator thread that reconciles devices (present && enabled) with active captures, one writer thread per segment (`writer`), and keeps `manifest.json` current (`manifest`). A session dir holds `manifest.json`, `tracks/<device>-<n>.flac` (`.wav` when `compression.live` is false) and `recording.pid` while live. With `compression.live` (default) the writer streams lossless FLAC through `flac_writer::FlacWriter` (16-bit for `i16`, 24-bit for `f32`), flushing complete frames every second; the FLAC header is written up front with no sample count and finalized on close. A crashed FLAC segment is repaired by `audio_file::repair_flac` (truncate to the last intact frame, write STREAMINFO) in `load_recovering`. Pause closes every segment but keeps the session open (`paused_since`/`paused_total` on `Active`; `reconcile` wants nothing while paused; `SessionStatus.elapsed` excludes paused time; `SessionStatus.bytes` is the session dir size, polled by the UI every 2 s while a session is active); resume opens new segments. Writers also tap what they write to `Recorder::subscribe_audio()` subscribers (`LiveAudio::Chunk`/`SegmentEnd`, session-time offsets, bounded `try_send` so a slow consumer never stalls recording). Every (re)start of a device is a new segment with `start_offset_ns` from session start; gaps in a stream are padded with silence. Segments left `recording` by a crash are repaired from the WAV header on load (`load_recovering`).
  - `transcript`: `transcript.json` and the live draft `transcript.live.json` load/save (`load_best` prefers the final one), `render` with `RenderOptions` (source/speaker/timestamps tags). `jobs`: file-per-task queue (kinds `transcribe`, `compress` and `summarize`, deduplicated per session and kind; a stopped session queues transcription first so it reads the original WAVs) under `$XDG_STATE_HOME/audio-recorder/jobs` shared by CLI and app; one worker at a time across processes via an flock on `worker.lock` (`JobStore::try_lock_worker`); cancelling a running task creates `<id>.cancel`; a worker start re-queues tasks left `running` by a dead process. Config `transcription` is resolved into `config::TranscriptionSettings`.
  - `audio_file`: `SegmentReader` reads WAV, FLAC (claxon) and Opus (ogg + libopus) segments by extension as interleaved f32 with `seek`; compressed formats seek through checkpoints (FLAC frame offsets learned while decoding, Opus page offsets scanned at open, 80 ms preroll). Everything that reads tracks (`mixdown`, `balance`, transcribe) goes through it, so never open segment files with hound directly. Opus is only used for 48 kHz mono/stereo (granule positions are 48 kHz units).
  - `compress`: the `compress` job. `compress_session` encodes each `.wav` segment (and, when `codec = "opus"`, each `.flac` one, so live FLAC is transcoded to Opus after transcription; `pending_segments(dir, settings)` uses the same predicate) to `<stem>.tmp.<ext>` (FLAC via flacenc streamed block by block, f32 stored as 24-bit; or Opus), verifies it by decoding, renames it, then rewrites `mix.json`, both transcripts and `analysis.json` and finally `manifest.json` (the commit point) before deleting the WAVs, so a crash re-runs cleanly. Config `compression` (`auto`, `live`, `codec`, `opus_bitrate_kbps`) resolves into `config::CompressionSettings`. `Segment.file` therefore may end in `.wav`, `.flac` or `.opus`; do not assume `.wav`.
  - `llm`: `complete(settings, system, user, cancel)` for the configured provider (`llm.provider`: Ollama `/api/chat` with `think: false`, retried without it for models that reject the field, or Anthropic `/v1/messages` with `anthropic-version` 2026-10-21 and no sampling parameters). Blocking `ureq` on a helper thread so cancellation is polled every 200 ms (the abandoned request ends at its timeout). The Anthropic key is `llm.anthropic.api_key`, else `ANTHROPIC_API_KEY` (resolved into `LlmSettings`, redacted in `Debug`). Refusals, `max_tokens` cuts and Ollama context overflow are errors, never saved as summaries. `input_budget` is the prompt size a provider accepts (Ollama: `num_ctx` minus output).
  - `summary`: `summary.json` load/save and `summarize_session`. It reads only the final `transcript.json` (never the live draft), renders it with timestamps, source and speaker tags, and asks for Markdown with `## Summary`, `## Key points` and `## Timeline`. A transcript over the input budget is split into line chunks, each condensed into notes, then combined by a last call. `Summary.transcript_created_at` marks a summary stale once the transcript is replaced. Config `summarization` (`auto`, `language`, `prompt`) resolves into `config::SummarizationSettings`. The file holds no segment names, so `compress` ignores it.
  - `library`: list/load/delete sessions. `mixdown`: `MixSource` mixes segments onto a 48 kHz stereo f32 timeline (linear resampling), optionally for one device, scaling each segment by its `mix` gain. `mix`: per-session `mix.json` (`MixSettings`: per-device and per-segment gain 0–4 and mute, `leveling`, `auto`; absent = unity; device settings are ignored when playing a single device's track). `balance`: BS.1770 gated loudness per device via `ebur128` (cached in `analysis.json`, keyed by segment file list) -> `auto_mix` (gains to -20 LUFS, clamped 0.25–2 so noisy mics aren't over-boosted, leveling on, `auto` true); `ensure_default` writes it when a finished session has no `mix.json` (app: after `SessionStopped` and on `get_session`, emitting `mix://changed`; also run by playback and CLI mixdown). `MixSource` applies an optional per-device RMS leveler (AGC, boost capped at +6 dB, gated by an absolute threshold and an adaptive noise-floor estimate so hiss isn't lifted) and always a master limiter (0.98 ceiling, 1 ms attack, soft-clip knee; never hard-steps the gain). `playback`: rodio playback of a `MixSource` on its own thread; `set_mix` applies new gains live at the next block boundary.
- `crates/transcribe` (`audio-recorder-transcribe`) — whisper-rs (CUDA by default via the `cuda` feature) plus sherpa-onnx diarization; kept out of core because of the native deps. `audio` decodes each device's segments (`core::mixdown::read_segment_mono`), resamples to 16 kHz with a built-in windowed-sinc and keeps a span map back to segment time. `whisper` finds speech regions with whisper-rs's Silero VAD (`WhisperVadContext`; the `FullParams` VAD flag is ignored by `whisper_full_with_state`, which is what states use) and transcribes each region separately, offsetting word times, so silent/noisy gaps never reach the decoder and cannot hallucinate text; one-word segments give word times, `diarize` yields speaker turns per device, `assemble` (pure) assigns speakers, groups words into snippets, maps to session time, interleaves all devices and numbers speakers globally (`S1`…, labels are per source: the same voice on two devices is two speakers). `models` resolves/downloads model files (explicit config paths are never downloaded). `worker` runs queued jobs through a `Runner` (`JobRunner` dispatches on the job kind). `Runner::follow_ups` lets a finished job queue more: a finished `transcribe` queues `summarize` (replace) when `summarization.auto` is set and the transcript has snippets, which covers app, CLI and every retranscribe. Binaries linking this crate need `build.rs` with `-Wl,-rpath,$ORIGIN` for the sherpa shared libraries (cli and app have it).
  - `live` (`LiveTranscriber`): consumes `LiveAudio` (a forwarder thread drains the recorder's queue into a byte-capped backlog), keeps a streaming 16 kHz resampler and buffer per device segment, endpoints with the VAD (commit after 0.6 s of trailing silence, or cut at the quietest point past 20 s), decodes with a smaller greedy model (`transcription.live.whisper_model`, default `ggml-small.bin`), saves `transcript.live.json` after each commit and emits `LiveEvent`s (committed snippets, partial text every 1.5 s, model status). The offline job still runs after stop and its `transcript.json` replaces the draft; the live model stays loaded between sessions.
- `crates/cli` (`audio-recorder` binary) — clap CLI over core.
- `crates/app` — Tauri 2 backend. Each command takes and returns `serde_json::Value`, validated through `schema::ipc` types in `commands::handle`. Tray (menu: show, start/stop recording, quit; icon changes while recording), close-to-tray, single-instance. The `LiveTranscriber` (when `transcription.live.enabled`) is started on `SessionStarted` and finished on `SessionStopped`; its events are forwarded as `live://transcript`. Core events are forwarded as `recorder://event` and playback state as `player://state`. A stopped session is enqueued for transcription (`transcription.auto`) and a worker thread is kicked (summaries are chained by the worker, not enqueued here; `enqueue_summary` / `get_summary` back the UI's Summarize and Re-summarize); a 1 s poller emits `jobs://changed` and also kicks a worker for tasks queued by the CLI. Quit (tray) with active tasks emits `app://confirm-quit`; the UI confirms and calls `quit_app(force)`, which stops the worker (the running task goes back to queued) before exiting. Tauri hooks run from `crates/`, hence `cd ui` in `tauri.conf.json`. `main()` sets `WEBKIT_DISABLE_DMABUF_RENDERER=1` (unless already set) because WebKitGTK shows a blank window with the NVIDIA proprietary driver on X11.
- `crates/ui` — Leptos 0.8 CSR built by trunk. `ipc.rs` wraps `invoke`/`listen` and validates every payload with the schema crate; components never touch raw JSON. `store.rs` holds the shared signals and event handling, `components/` the UI (controls, devices, summary section (Markdown through `markdown.rs`, which turns raw HTML, links and images into plain text), live transcript panel (shown while a session is active, fed by `live://transcript`), sessions, tasks tab, transcript section, player bar, confirm dialog). Colors: `style.css` has no color literals, only `var(--token)`; `theme.rs` bundles `themes/*.theme.json` (validated by the theme schema; light, dark, six gruvbox variants) and injects one `<style id="app-theme">` block: `:root` defaults follow `prefers-color-scheme` (the "system" choice, built from the `light`/`dark` themes) plus a `:root[data-theme="<id>"]` rule per theme. Choosing a theme sets `data-theme` and persists it via the `get_settings`/`set_settings` commands. To add a theme: drop a file in `themes/` and add it to `SOURCES`. Playback is disabled in the UI (with an explanatory tooltip) and rejected by the backend while a session is active (recording or paused), and starting/resuming a recording stops playback, because playback audio would be captured by the output monitors.

## Commands

- Test (schema, core, cli): `cargo test`; everything: `cargo test --workspace`
- Hotplug integration test (needs PipeWire + pactl): `cargo test -p audio-recorder-core --test hotplug -- --ignored`
- Run the CLI: `cargo run -p audio-recorder-cli -- <subcommand>`
- GUI dev: `cd crates/app && cargo tauri dev`; self-contained binary: `cd crates/app && cargo tauri build --debug --no-bundle`
- Transcribe without CUDA: `cargo build -p audio-recorder-transcribe --no-default-features`
- Check the UI and schema crates for wasm: `cargo check -p audio-recorder-ui --target wasm32-unknown-unknown`

## Testing the GUI headless

Use a private Xvfb (`:98`, never `:0`) and isolate state: run from a scratch dir with a `config.toml` setting `sessions_dir`, and set `XDG_STATE_HOME`. To see the tray, start an i3 on the Xvfb with `bar { tray_output screen }` and a short `ipc-socket /tmp/x.sock` (long socket paths silently collide) before launching the app; never touch the user's own i3 (pid on `:0`). Test sinks: `pactl load-module module-null-sink sink_name=x media.class=Audio/Sink` (without `object.linger`, which keeps the node after unload).
